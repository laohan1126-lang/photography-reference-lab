# v0.2 架构与状态契约

## 目标与技术选择

一个所有者，多角色项目。重点是可追溯参考、人工审美选择、现场可读口令与长期笔记，不是公开图库、摄影商业 SaaS 或无人审核的素材爬虫。

- `ref_lab/api.py`：同源 FastAPI API、口令会话、权限保护、输入模型与文件边界。
- `ref_lab/service.py`：唯一领域用例层；Web、CLI、迁移与执行器共用，不在前端重复决定发布资格。
- `ref_lab/db.py`：SQLite WAL、外键、事务、索引、schema version。适合当前单所有者服务；暂不支持多实例并发分布式任务队列。
- `ref_lab/storage.py`：内容寻址原始文件与衍生展示图。数据库只保存元数据和引用。
- `ref_lab/policy.py`：显式门槛与状态推导。未知不通过，不设“默认适合实拍”。
- `ref_lab/imports.py`：候选包、Notion Markdown/CSV 与历史批次迁移。
- `ref_lab/collector.py` / `providers.py`：可选本地采集、Responses API 分析、Notion 任务摘要同步。
- `web/`：无需 Node 构建的浏览器界面；只通过 API 持久保存，不把 localStorage 当数据库。

## 数据实体

Project 保存角色、作品、版本、自由要求和器材。Asset 按收到的文件字节 SHA-256 唯一，记录解码后的真实尺寸、格式、大小、近似哈希和存储位置。Reference 将某个 Asset 用于某个 Project，保存来源、人工选择、借鉴维度、审美反馈、逐图核验、资料卡和拍摄复盘。

同一个 Asset 可以供多个项目引用；同一个项目不重复建立相同字节的 Reference。重复来源附加到 discovered_sources，而不覆盖原选择。候选导入别名以 `(project_id, import_key)` 去重；同名但图片字节改变时拒绝静默覆盖，必须显式替换。

Job 保存检索计划、自由要求、状态、实际导入/分析结果以及分析开始时的图片和版本快照。Note 保存原导入标识和可编辑内容；修改内容不改变去重指纹，防止重复导入覆盖用户修改。Event 是应用层只追加事件，不宣称具备防管理员篡改能力。

所有可编辑实体使用 revision 做乐观并发控制。过期写入返回 409，不做后写覆盖。事务保证选择、事件与索引状态一致。

## 现场卡门槛

必须同时满足：

1. 用户选择 KEEP，归档方向为 field，实际文件存在且未被完整性检查标记损坏。
2. review 绑定当前 asset_sha，类型是真人 cosplay 或普通真人摄影；人物可见、动作可辨、独立画面、清晰度够用，无关键未决疑点。
3. 角色关系明确；跨角色或普通人像借鉴需用户显式允许，不冒充同角色参考。
4. 来源经用户确认，可追溯至实际发布页；搜索页/CDN/图片地址不能冒充原发布页。自有作品需提供来源/权利说明。
5. card 存在，且 card_context 与当前角色要求/器材一致。
6. 用户对当前图、核验、来源与卡片指纹进行独立确认。accept 时和导出时重新校验原始文件 SHA。

状态包括 candidate、needs_review、needs_card、draft、ready、rejected、inspiration、missing_asset。它们是策略推导结果，不由浏览器随便写入。AI 结果可给出核验建议，但不会自动产生用户验收记录。

修改来源/选择/反馈/借鉴方式会撤销旧确认。修改项目角色或要求会撤销受影响的确认，保留旧卡等待重做/核对。替换图片会清空 review、card 和 confirmation，重置选择为 pending；旧 Asset 保留。doctor 检出损坏后撤销相关确认，修复文件后仍需要重新确认。

## 图片与画质

“原始文件”仅表示系统收到的字节，不保证是摄影师相机原文件或平台最高分辨率。收到的字节保持不变；预览图和缩略图分别生成，允许有损压缩但绝不覆盖原始文件。迁移时无法确认原采集／转存过程的旧文件保持 unknown；确认发生过转存后可标记 legacy_reencoded，不能宣称重新获得无损原图。

近似哈希用于发现疑似重复，不自动淘汰。所有入库尺寸来自实际解码，不盲信 manifest 声明。单图审阅保留完整画面，列表缩略图不作为最终参考交付。

## 执行器与成本边界

项目要求作为原始自由文本完整传给任务包与分析模型。本地采集器只提供基础搜索词和可见页面图片采集，不伪装成已经理解全部自然语言条件的智能搜索代理。增强检索规划由 Codex/Antigravity 读取任务包执行，或后续增加独立 planner。

分析任务只接受已保留图片，绑定创建时版本；执行过程中内容变化会拒绝过期结果。已完成条目按检查点保存，重跑不重复收费调用已经完成的条目；未确认服务端是否完成的网络失败不会盲目自动重试。任务成功要求存在实际结果，不能仅写一个 succeeded。

本地浏览器采集需要用户已授权的 CDP；保持用户浏览器开启，不上传 Cookie。验证码、风险提示、访问错误会停止采集并保留结果。默认不联网抓取、不付费分析、不自动部署、不自动生成图片。

## 离线、备份、迁移

离线 ZIP 内有独立图片与完整静态 HTML，不依赖 service worker、远程 CDN 或手机现场网络。现场包只接受已确认条目；灵感包明确不是拍摄指令。离线文件不可远程撤回，也不自动同步复盘；主数据源仍是服务端数据库。

备份使用 SQLite backup API 的一致快照，并包含对应 Asset 文件，不包含口令与外部 API 密钥。恢复时停服务、使用全新空数据目录、运行 doctor，再用新口令启动。

历史导入只读旧目录，重复运行幂等。缺图保留为 missing_asset，不下载猜测路径。修复缺失图后使用显式替换或补齐原字节并检查，不把再次导入变成隐式图片覆盖。

## 当前不宣称的能力

未提供多账号权限模型、自动云端浏览器调度、模型视觉准确率保证、自动 PS 执行、AI 背景生成 API、跨设备离线编辑同步、Notion HTML 保真渲染、域名 DNS/TLS 自动配置。当前 CI/测试不替代用户现场验证或素材授权判断。
