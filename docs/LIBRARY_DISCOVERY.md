# 图库：跨项目找图，而不是继续增加分类项目

从导航进入「图库 · 跨项目找图」。先看网格，组合条件找到图片，再点开图片进入它原来的项目继续筛选或制卡。全局图库同一资产只出现一次，但会列出各个项目独立的保留/待定/淘汰关系。

例如：范围「本角色参考（K）」＋视角「仰拍」＋景别「全身」，可以跨角色寻找适合借鉴的站位。限定某个项目时，K 必须属于这个项目，不会借用另一个项目的 K 来满足条件。「我的审美收藏」仍然只包括独立收藏，项目 K 不自动成为审美收藏。

## 不需要先整理整个旧图库

标题、作者、项目和审美笔记可以直接搜索。横/竖/方幅来自实际资产尺寸；图片类型来自已存在且绑定图片的观察记录，仍可能需要复核。视角、景别、主动作使用图片详情里的明确摄影分类，未标注保持「尚未分类」。本轮没有根据标题、搜索词、角色名或淘汰理由自动生成图像事实，也没有部署新的视觉模型。

可以先给经常用的少量参考补标签。分类只是检索线索；保存分类不会改变 K/I/M/X、审美画像、VisualReview、角色适配或现场卡验收。新字节是不同的资产，不继承旧字节的分类。不要为了填标签而重新导入、覆盖或修改原图。

## 常用搜索与项目导航

「保存当前搜索」保存已经点过「查找」的条件；新图符合条件会自动出现。它不是固定选集，不记录图片成员、顺序或模特沟通备注。最多保存 40 个查询；删除查询不删除图片。查询存在服务器 SQLite，手机和电脑共用。

侧栏默认最多显示 8 个当前、置顶或最近打开的项目。项目可以搜索、置顶（最多 8 个），其余通过「全部项目」按每页 30 个打开，手机也能进入。置顶和访问记录独立于项目要求、revision 和摄影反馈。目前沿用已有项目元数据列表接口，不宣称后端项目列表也已经分片分页；限制的是导航和目录 DOM。图库的图片筛选、计数与分页由服务端 SQL 执行，每页默认 60 张。

默认图库隐藏只有淘汰、移出、已归档或预检过滤关系的资产；独立审美收藏仍可使它出现在全局图库。它不是删除后的垃圾桶，恢复继续使用原有项目回收/过滤入口。

## 采集判断边界

「翅膀」「假发」「搭子」等单个泛词不再作为确定性拒绝理由；明确招募、出租、出售、教程等仍保留拦截。作者昵称和 URL 路径不再参与负向意图关键词匹配。

近白像素占比大于 60% 不再直接判成商品或文档。保留原图，在 discovery_reason 记录比例并说明需要看图；不写伪造的 preflight，也不记成用户审美负反馈。这个提示仍不是视觉分类器：既不保证广告不进入，也不保证照片好看。真实筛选质量必须通过本机候选和用户判断验收，不使用合成测试冒充准确率。

## 存储、备份与下一阶段

本轮只增加 library_annotations、library_saved_searches、library_project_navigation 三个扩展表和一个 refs.asset_sha 索引，在应用初始化事务中幂等创建。不改原有表内容，不提升 schema 3，不改变 CAS 或项目引用。SQLite 完整备份/恢复会包含新表；测试覆盖重启、完整备份恢复、冲突拒绝和原选择不变。旧版本不使用这些扩展表，禁止手动删表或回写数据库来“修复”界面。

后续独立阶段才处理：代表性例图检索、实际 Skill 版本加载与同批候选新旧对照、近似图比较、固定拍摄清单、在线/离线现场卡统一。此版本不声称已完成自动审美学习或个性化排序。
