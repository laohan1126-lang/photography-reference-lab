# 恢复先输入角色再搜图

## 原始请求与编辑前判断

用户：“开始取景这里为什么拍摄项目变成了固定的一些选项，这不是应该是我输入角色，然后再去找图片的吗？……先把这个问题给我修复了。”

基线 `0378a654`，工作树干净；本轮事务 `01a178d9-e9de-7a73-bc54-ff24ca34cd9c` 已在首个修改前建立，沿用其绑定的任务分支。

根因：上一轮把全局“开始取景”绑定到 `state.project ? collectionEditor() : projectEditor()`；页面会自动选中首个项目，因此正常有图库时只能先看到已有项目下拉框。旧测试只验证下拉框绑定正确，没有验证用户应先输入任意角色，验收标准遗漏。

读取并追踪了 projectEditor/collectionEditor 所有调用方、现有表单/API、相关 UI 测试以及上一轮 UI/历史完整性回执。方案：复用角色输入表单，为“保存后进入搜图设置”提供明确衔接；全局入口先填角色，当前项目内加搜继续绑定当前角色。普通新建/编辑与收藏引用流程保持。

可见验收：有/无旧项目，“开始取景”和“采集任务→建立搜图任务”都先出现空白角色输入；填写角色/作品/服装/要求，继续后搜索设置绑定刚保存的角色。保存前不创建项目，明确开始前不创建采集 Job；实际提交后的 Job 绑定新角色。旧项目和两种搜图模式保留。

只改前端流程与对应回归，不改采集门槛、后端接口、schema 或原始图库。不在主人库创建测试项目/任务，不执行新联网采集。正式交付仅本任务路径，Notion仍关闭。
