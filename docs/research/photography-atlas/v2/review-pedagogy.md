# V2 教学设计独立复核

复核对象：`.local/atlas-v2/docs/research/photography-atlas/GATEWAYS.json`、`V2_DESIGN.md`、`web/learning-gateways.js`。我在 `http://127.0.0.1:18766/learning` 的真实预览中逐一打开三条入口，并跳转到三张迁移图；没有改动产品文件或 Git。

## 结论

三条课的核心学习活动不是背术语：第一条让学习者从像素线索预测注意顺序并检查边界，第二条要求区分位置、朝向、距离、姿态和取景，再设计能推翻自己假设的对照，第三条要求从脸部阴影读光向、区分环境曝光与闪光贡献，并预测转脸或补光会改变什么。三种认知操作确实不同；共同的“问题—观察—原理—对照—边界—迁移—回看”结构只是导航骨架，不构成同质化。

答案揭示时机总体合格：观察题先出现，讲解是默认收起的原生 `<details>`，没有自动判分或因阅读而升级。读者可跳过回答、主动提前展开；这符合低压力要求，但“先试再看”是教学提示，不是强制顺序。预览首屏也没有直接露出迁移题分析。当前主要问题是迁移图在阅读器中全部触发加载失败，以及第一条课的迁移任务没有检验标题/结果承诺中的遮挡边界能力。

## P1：三张许可迁移图在实际阅读器中都加载失败

在本地预览分别打开第一条 `transfer-nightscape`、第二条 `new-character`、第三条 `window-transfer`，三个位置都显示“图片暂时无法加载，请打开下方原案例。”占位框，没有显示照片。它们正是三课用来检查新场景迁移的关键材料；没有图像时，学习者无法在阅读器里按题目先独立观察，只能额外打开原始文件页，迁移流程因而中断。

实现位置：[learning-gateways.js](../../../../web/learning-gateways.js#L34) 的 `caseHTML` 对有许可图片输出远端 `<img>`；第 40 行的失败处理会隐藏图片并显示占位提示。对应数据在 [GATEWAYS.json](../GATEWAYS.json#L324)、[#L662](../GATEWAYS.json#L662)、[#L1004](../GATEWAYS.json#L1004)。我还在浏览器中分别打开了这些精确缩略图 URL 的独立标签，文件标题/像素尺寸均正常出现；因此目前证据指向“嵌入阅读器的请求或加载上下文”，不能据此断言 Commons 图片源已失效。

最小修正：先查实际嵌入请求的网络/控制台失败原因，再修复远端图片嵌入或提供经许可、原样并保留署名与来源的本地展示路径。验收应逐一确认三张图在各自迁移段真实呈现，且刷新、重新打开入口后仍可见；不要只以链接可打开或占位文案存在作为通过。

## P2：注意力入口的迁移题没有检验其承诺的遮挡边界能力

`attention-and-occlusion` 的 `outcome` 同时承诺：预测视觉主次、指出可见线索、检查遮挡边界是否帮助分层/造成粘连；但迁移题 `transfer-nightscape` 只要求记录第一眼落点及继续观看时注意点是否变化。展开分析还明确说明该夜景图“不是为遮挡/轮廓粘连设计的控制例”，并说无需强行找遮挡（约 `GATEWAYS.json` 第 531–549 行）。这对单张图片的边界诚实是正确的，却意味着读者完成了迁移题仍没有展示该课另一项结果。

最小修正二选一：把该入口的可迁移结果收窄为注意竞争/注意预测，并明确遮挡边界是在原案例中学习的观察维度；或保留合并结果，改用确有清楚遮挡边界的新图，并在迁移题只增加一项有像素依据的边缘判断。不要要求学习者在现有夜景图中臆造遮挡案例。

## 其余审查项

- **教学链条：** 第二条从 16 格成片的多变量混淆，转到“固定姿态、后退并恢复取景”的可检验对照；这清楚说明为什么先讲变量再讨论镜头术语。第三条从脸转向的阴影变化，到环境/闪光序列，再到窗边新照片预测，观察、原理、限制和实拍验证相互衔接。第一条的原始盐沼两帧与中心人像提供不同表达选择，避免把三分法或“干净背景”讲成普遍规则。
- **专业边界：** 课程多次区分像素可见事实、摄影师原文解释、项目推断和未知条件；第二课不从单张照片反推精确机位，第三课不从成片倒推精确灯位/光比，第一课不把注意预测冒充眼动测量。这些限制没有把练习退化为术语表，反而要求说明证据及可检验预测。
- **未发现答案过早泄露：** 关键像素分析均在折叠解析中；迁移题原图标题也隐藏了会提示注意方向的原文件名/图说。问题段提供方向性提问，但没有直接给出该张迁移图的观察结论。由于回答可跳过、解析可随时展开，不应把“没有强制提交后才能揭晓”当作失败；若要提高顺序感，最小改动是强化“建议先写下判断，再展开；也可跳过”的提示，而不是加考试门槛。
- **三种样板差异：** 第一课练注意预测与边缘辨认；第二课练变量拆分与对照设计；第三课练光线诊断与拍摄干预。当前差异落在学习者实际要做的推理上，而不只在题材和标题上。

## 实际预览证据与范围

复核页面：`http://127.0.0.1:18766/learning`，浏览器实际打开三条入口并在迁移章节观察图片占位。故“迁移图未显示”为当前预览中直接观察到的行为；我没有检查服务器日志或浏览器网络面板，嵌入失败的底层原因仍未确定。此次是教学设计审查，不是对所有摄影技术主张的完整来源重审，也未做学习者试用或真实学习效果测量。

## 修订后复核：关闭状态

主代理修正后，我重新打开隔离预览 `http://127.0.0.1:18766/learning`，依次检查三条课程各自的迁移段。三张 Commons 许可图最终都在阅读器中实际显示：夜景建筑与小人物、蒸汽朋克人物与道具、窗边人像。夜景与窗边图在滚到题目后约3–4秒显示；蒸汽朋克图首次进入后等待约13秒仍为空白，切换到另一入口后再回来约4秒才显示。此前 P1“迁移图始终加载失败”本轮未再复现，但蒸汽朋克图的冷加载稳定性仍未确认，建议继续留意延迟/失败情况。此结论限于三张图在本次浏览器会话中的呈现；未审查CSP策略对其他路由或请求的隔离行为（实现没有图片代理）。

第一课的旧 P2 也已关闭：入口标题现在是“先看见什么：画面里的注意力竞争”；结果明确只训练注意预测，并把遮挡列为相邻可选检查、声明本课不认证遮挡分析能力。技能映射不再包含前景遮挡控制。新迁移题先让学习者记录自然的第一眼，再自选表达目标、引用两处画面线索、提出拍摄调整并预测注意竞争变化与可能代价/替代解释；分析仍默认折叠。这样既保留新场景迁移，也不要求从夜景图中臆造遮挡。

**最终复核结论：**第一课的目标与迁移对齐问题已修正；三课图片均能在本轮预览中显示，但第二张首次加载延迟，冷加载稳定性还未充分验证。三课的任务认知仍各不相同，答案揭示时机仍符合低压力的“建议先答、可跳过”设计。此复核不能证明真实学习者已经掌握这些能力，也未重新审计技术内容、版权判定或完整产品回归。
