# 摄影能力地图：信息架构决定

此决定基于独立抽取后形成的 14 个领域、70 个模块与 235 个初步技能；节点数会随来源与覆盖审查变化。不是为了适配页面而压缩研究。

## 候选比较

| 方案 | 优点 | 问题 | 决定 |
| --- | --- | --- | --- |
| 全屏节点连线图 | 先修关系可一览 | 二百多个节点在手机上难读；连线暗示没有证据的固定学习顺序，摄影图片被挤成装饰 | 不采用 |
| 图片领域索引 → 模块目录 → 技能研究页 | 照片保持视觉主体；每次只展开一层；完整目录与研究证据仍可访问；未知、训练中与本人记录分开 | 需要面包屑、搜索和历史返回支持，不能只做好看的首页 | 采用 |
| 训练计划作为首页 | 下一次练习很直接 | 默认计划容易把未评估当不会，完整能力边界被隐藏；也容易变成任务管理器 | 仅把“下一次练习”作为依据明确的入口 |

## 采用的结构

- 首页是不同高宽比的摄影领域入口，不展示二百多个技能，不用统计卡或进度条。领域文字与图像自然关联。
- 领域页用一个视觉开篇和连续模块目录；模块页用清晰的技能条目而非等高卡片，展示本人状态。
- 技能页提供可执行能力、失败表现、单变量练习、项目验收、原文出处、关联案例链接、我的照片与学习记录。分段排版；来源位置与支持命题能展开查看。
- 专业证据不使用私人封面图来证明。专业图例目前为原教程链接，明确未作图像像素审阅。用户附图与备注只属于个人记录，不会改写专业依据。
- 所有初始状态是“未评估”；“未开始”需要本人选择。训练中、本人确认已掌握、薄弱标记与当前重点分别保存。状态不由阅读、勾选或上传照片自动提升。
- 下一次练习优先本人指定重点，其次本人标记薄弱；没有这些记录时，邀请从核心能力做第一次评估，并说明选择依据，不推断用户水平。
- 搜索覆盖领域、模块、技能、失败表现、真实问题入口与公开研究缺口；短匕首等未证实问题必须显示“资料不足”，不能悄悄跳到长剑方法冒充答案。

## 验收与迭代

固定种子抽选五条完整路径及五条未训练能力；测实际浏览器中“仰拍为什么没有气势”的查找耗时；验证选择重点后下一次练习与原技能对应；刷新保存个人记录；检查返回拍摄参考后仍能回来。桌面与移动端实拍页面截图后再判断布局，不能以 CSS 数值推定美观。

研究全面性、工程测试和主人审美验收是三项不同结论。此文不表示所有验收已通过。

## 首轮实际截图后的调整

1440px与390px真实Chromium截图没有横向溢出或脚本错误，但手机首屏被介绍、推荐和多行筛选占满，领域图片尚未出现。这违反照片索引优先的信息顺序。调整为更短的首次评估邀请、紧凑推荐、单个可含状态/重点/薄弱的手机筛选入口，并将封面证据边界放到页脚。技能页隐藏内部ID和非交互标题的焦点边框，保留按钮的键盘焦点；不压缩技能树或删除未知边界。之后重新截图验证。

第二次截图验证：手机390×844首屏可见领域图片，桌面1440×1000首页、领域、模块与技能均无横向溢出；实际页面未出现脚本错误。问题检索0.593秒。根任务查看了私有截图，未把封面当作摄影图像事实或主人审美验收。实际日用18765服务已可读取247技能bundle与独立学习状态（当前零记录）；没有重复重启。

## 主人要求复核后的学习入口

技能页优先展示可直接打开的配套教程，每项包含作者、起读段落或视频章节与读后练习。默认最多展开两份，其余材料和推荐边界可展开；正式研究依据继续保留在独立折叠段落。没有专门推荐时明确提供原文阅读，不填造课程或观看经历。

四个轻量文字入口跳到教程、最小训练、研究依据和我的记录，保留当前技能 URL。个人记录侧栏不再撑满长文高度。实测同时修复了从首页底部进入专题时保留旧滚动位置、个人筛选未进入历史以及弹窗保存目标随路由改变的问题。分歧只按已审查技能映射显示，避免同一本教材的其他主题干扰阅读。

1440×1000 / 390×844 的追加截图覆盖首页、领域、模块、技能、教程、个人记录、搜索与缺口页面；原文阅读的英文标题保留来源原名，精选教程使用中文导读。实际截图与测试证据记在任务文档，不以无溢出等同主人审美接受。
