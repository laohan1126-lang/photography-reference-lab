你现在接手 Photography Reference Lab 的「摄影能力地图」建设。

目标不是写摄影教程，也不是根据你自己的常识生成一份“摄影知识大全”。

最终目标是：

建立一棵“预先长完整”的个人摄影技能树，让我能够清楚知道：
1. 一个以 Cosplay / 人像现场拍摄为核心、目标达到很高专业水平的摄影师，需要具备哪些能力；
2. 每项能力下面还有哪些具体可训练技能；
3. 哪些我已经掌握、哪些正在训练、哪些还没有开始；
4. 每个技能如何训练、如何验收；
5. 所有重要节点都必须能够追溯到真实专业摄影资料，而不是模型凭知识补全。

当前已有 UI 只是原型。
不要把现有 10 个专题当作最终正确分类，它们只能作为 seed / hypothesis。
允许拆分、合并、重命名、新增一级领域。

━━━━━━━━━━━━━━━━━━
一、核心研究原则
━━━━━━━━━━━━━━━━━━

禁止直接依赖模型已有摄影知识生成最终技能树。

你的内部知识只允许用于：
- 提出搜索关键词；
- 猜测可能存在的领域；
- 帮助比较不同资料；
- 发现可能遗漏的方向。

任何正式进入能力地图的内容，必须有外部证据。

优先来源按以下等级处理：

Tier A｜高可信专业来源
- 顶级职业摄影师本人网站、博客、课程、访谈
- 成熟摄影教育机构
- 摄影协会、专业学校、工作坊
- 摄影器材厂商的高质量专业教育内容
- 高水平摄影书籍作者公开资料
- 有长期职业作品与教学记录的摄影师

Tier B｜高质量专业视频
- YouTube 上职业摄影师本人
- 知名摄影教育频道
- 有完整实拍过程、分析、案例对照的长视频
- 摄影师讲解自己的实际拍摄逻辑

Tier C｜视觉案例发现
- Pinterest
- Behance
- Instagram
- 小红书
- X
- 摄影作品站

注意：
Pinterest 等平台主要用于“发现案例和视觉模式”，不能单独作为摄影原理的权威证据。
如果 Pinterest 找到一张重要案例，尽可能追溯摄影师、原始作品、教程或其他可靠出处。

避免：
- SEO 农场文章
- AI 自动生成摄影教程
- 无作者身份的“十大摄影技巧”
- 单纯转载
- 只有漂亮图片但没有专业依据的结论
- 为了凑数量重复同一条知识

━━━━━━━━━━━━━━━━━━
二、目标摄影师画像
━━━━━━━━━━━━━━━━━━

能力树服务的目标不是“所有类型摄影全能”。

目标画像：

以真人 Cosplay / 人像现场摄影为核心，
需要能够稳定完成：

- 构图和视觉组织
- 人物比例与透视控制
- 机位与焦段选择
- 人物姿态与重心指导
- 人物和大型/小型武器、道具的空间组织
- 自然光判断与使用
- 闪光灯 / 单灯人物塑形
- 环境人像
- 角色气质和情绪表达
- 现场快速观察与调度
- 景别设计和组照变化
- 动态动作拍摄
- 漫展复杂背景处理
- 后期成片
- 色彩与风格
- 基础动态影像 / 运镜
- 拍摄前设计与拍摄后复盘
- 能够发现自己的失败原因并设计下一轮验证

重点适配：
中国漫展 / Cosplay / 少女人像 / 外景与场馆现场。

不要把商业产品摄影、体育、鸟类、建筑、婚礼等无关领域大量塞进核心树。
必要时可以作为“扩展技能”。

━━━━━━━━━━━━━━━━━━
三、能力树必须至少分三层
━━━━━━━━━━━━━━━━━━

L1：能力领域
例如：
构图与视觉组织

L2：能力模块
例如：
画面边缘管理

L3：原子技能
例如：
关节截断判断

每个 L3 必须是真正可以单独训练和验证的能力。

不要出现这种假节点：

“提高审美”
“学会构图”
“增强摄影感”

必须转成可以观察和练习的能力。

例如：

错误：
学会仰拍

正确：
能够区分“降低相机高度”和“增加镜头仰角”造成的不同视觉效果，并主动控制人物比例和背景垂直线。

━━━━━━━━━━━━━━━━━━
四、每个原子技能的数据结构
━━━━━━━━━━━━━━━━━━

每个 L3 至少包含：

1. skill_name
技能名称

2. capability
到底要会什么

3. why_it_matters
它解决什么真实拍摄问题

4. prerequisites
前置能力

5. failure_modes
不会这一项时，照片通常会怎么失败

6. practice
最小训练方法

7. acceptance
做到什么才算真正掌握

8. evidence
支持这项能力的专业来源

9. visual_examples
如果存在，附专业作品 / 教程案例

10. relevance
core / important / advanced / optional

11. status
先全部设置为：
unassessed

后续系统再使用：
unstarted
learning
practicing
field_verified
mastered

12. confidence
high / medium / low

confidence 必须依据资料覆盖情况，而不是模型主观自信。

━━━━━━━━━━━━━━━━━━
五、研究 Loop
━━━━━━━━━━━━━━━━━━

不要一次直接生成最终树。

严格执行以下 Loop。

PASS 1｜广泛源扫描

先不要写技能树。

搜索：
- portrait photography curriculum
- professional portrait photography skills
- composition masterclass photographer
- posing professional photographer
- lens perspective portrait
- environmental portrait
- flash portrait lighting
- editorial portrait photography
- cosplay photography professional
- action portrait photography
- cinematography camera movement
以及中文、英文、日文资料中有价值的对应内容。

建立 SOURCE MAP。

每条来源记录：
- 作者
- 身份
- 来源类型
- URL
- 主要覆盖领域
- 为什么值得信任
- 是否值得深入

先广覆盖，再深入。

——————————

PASS 2｜独立抽取能力

从来源中抽取“摄影师真正反复训练和控制的变量”。

这一轮不要强行套进现有十分类。

生成大量候选技能。

记录：
source → claimed skill

例如：

某摄影师反复强调：
foreground / subject / background separation

不要立即归类成“构图技巧”。

先记录为候选能力。

——————————

PASS 3｜聚类成树

当候选技能达到足够规模后，再进行聚类：

L1
 → L2
   → L3

目标规模不是硬指标，但预期应该达到：

约 8–15 个 L1
约 50–100 个 L2
约 180–300 个 L3

如果最后只有几十条，优先怀疑覆盖不足。

如果达到五六百条高度重复技能，则进行合并。

——————————

PASS 4｜Coverage Audit

建立缺口检查。

至少从以下角度分别审计：

A. 拍摄流程
拍前 → 观察 → 构图 → 指导 → 拍摄 → 检查 → 后期 → 复盘

B. 技术
曝光 / 对焦 / 快门 / 景深 / 焦段 / 透视 / 闪灯 / 色彩

C. 视觉
构图 / 光线 / 色彩 / 层次 / 形状 / 视觉重量

D. 人物
姿势 / 重心 / 手 / 腿 / 肩胯 / 表情 / 视线 / 动作

E. Cosplay 特殊能力
服装
假发
大剑
匕首
宽袖
裙摆
大型道具
角色表现
复杂漫展环境

F. 场景
室内
室外
树林
建筑
窗边
强逆光
夜景
漫展场馆

G. 执行
快速判断
与模特沟通
连续变化
现场调整
失败发现

H. 后期
筛片
肤色
局部光影
背景清理
色彩
合成边界
最终输出

I. 动态
人物运动
相机运动
起点 / 过程 / 终点
简单镜头语言

发现空白后：
重新搜索。

禁止直接用模型知识补洞。

——————————

PASS 5｜Source Triangulation

对于重要 Core 节点：

尽量寻找至少 2 个相互独立的专业来源。

如果只有一个来源：
标记 medium confidence。

如果只是模型推断：
不能进入正式树。

如果不同专业摄影师观点冲突：
保留冲突，不强行平均。

记录：
- 共识
- 条件差异
- 不同流派

——————————

PASS 6｜Atomicity Audit

逐项检查：

这个节点能不能单独练？
能不能看到失败？
能不能设计实验？
能不能判断通过与否？

如果不能，则继续拆分或重写。

例如：

“背景控制”
过大。

可以拆成：

- 边缘干扰检查
- 头部背景分离
- 明暗分离
- 色彩分离
- 景深分离
- 前景遮挡
- 背景信息密度控制

——————————

PASS 7｜95分目标审查

问：

如果一个摄影师把 Core 和 Important 中的大多数能力真正稳定掌握，
是否已经足以成为非常强的 Cosplay / 人像摄影师？

如果答案是否定：
继续查漏。

同时防止：
为了追求“完整”，把摄影百科全部塞进去。

━━━━━━━━━━━━━━━━━━
六、我的真实学习只用于第二层修正
━━━━━━━━━━━━━━━━━━

现有真实问题可以帮助检验树：

- 人物前倾导致头大身小
- 低机位没有产生气势
- 大剑进入画面后人物显得太小
- 匕首内扣 / 外展
- 逆光脸部曝光
- 荷兰角什么时候成立
- 膝盖截断
- 背景杂乱
- 宽袖人物姿态
- 手伸向镜头
等等。

检查这些问题是否能够在能力树里找到明确位置。

如果找不到：
说明树可能遗漏能力。

但不要反过来只围绕我的历史问题建树。

树必须比我目前已经遇到的问题更完整。

━━━━━━━━━━━━━━━━━━
七、UI 设计任务
━━━━━━━━━━━━━━━━━━

技能树研究成熟以后，再设计 UI。

不要先为了页面漂亮而压缩能力结构。

当前视觉方向：
- 象牙白 / 米白背景
- 粉蓝 / 冷蓝作为强调色
- editorial photography 感
- 摄影图片主导
- 不做企业 Dashboard
- 不做大量彩色进度条
- 不做几十个圆角卡片堆砌
- 不做游戏风廉价技能树

但必须明显表现：

已掌握
正在练
未开始
发现薄弱
当前重点

推荐采用“地图 / atlas / editorial index”的语言。

首页：

摄影能力地图
↓
L1 大领域

进入领域：

L2 模块结构
+
完成状态
+
正在训练节点

进入模块：

完整 L3 技能树

进入技能：

专业资料
案例
我的照片
训练任务
验收标准
学习记录

需要支持：
progressive disclosure

也就是平时看地图不会被 200 多个节点淹没，
但需要时可以一路展开到底。

请自行设计 2–3 个 UI 信息架构候选，
自己进行 critique，
选择最符合上述目的的一版实现。

视觉美观不是唯一标准。

第一优先级是：

“我打开它以后，马上知道我还有什么不会。”

━━━━━━━━━━━━━━━━━━
八、UI 自我验收 Loop
━━━━━━━━━━━━━━━━━━

实现后必须自己检查：

1. 随机选择 5 个能力：
是否可以从 L1 一路找到 L3？

2. 随机选择 5 个未训练能力：
是否很容易看出来它们没有掌握？

3. 给定一个真实问题：
“仰拍为什么没有气势？”
能否在 30 秒内找到相关能力？

4. 给定：
“我下一次应该练什么？”
界面是否能回答？

5. 页面是否因为内容多变成难看的表格 / Dashboard？

6. 移动端是否还能理解技能树结构？

发现问题：
回到信息架构调整。

不要只打 CSS 补丁。

━━━━━━━━━━━━━━━━━━
九、研究输出要求
━━━━━━━━━━━━━━━━━━

必须保存：

SOURCE_MAP
所有主要来源

SKILL_TREE
完整 L1/L2/L3

EVIDENCE_MATRIX
skill → source

GAP_AUDIT
检查过哪些维度、仍有哪些不确定

CONFLICTS
摄影师之间存在分歧的地方

UI_DECISION
为什么选择当前 UI

不要只把结果写进页面代码里。

研究材料必须独立保存，未来可以重新构建 UI。

━━━━━━━━━━━━━━━━━━
十、停止条件
━━━━━━━━━━━━━━━━━━

只有满足以下条件才认为第一阶段完成：

- 技能树达到足够细度
- Core 领域没有明显大块空白
- 重要技能有外部来源支撑
- 已做至少两轮 coverage audit
- 已做一次反向查漏：
  从真实摄影任务出发检查树
- 已做一次来源质量审查
- 已做一次技能原子性审查
- UI 能表现完整树而不淹没用户
- 明确区分：
  专业共识 / 某摄影师方法 / 项目推断 / 用户个人经验

如果任何一项没有满足：
继续 Loop。

不要因为页面已经能运行就宣布完成。

━━━━━━━━━━━━━━━━━━
十一、Agent 使用
━━━━━━━━━━━━━━━━━━

如果支持子 Agent，请主动并行派发，而不是一个 Agent 从头写到尾。

建议至少拆成：

Agent A
构图 / 视觉组织

Agent B
焦段 / 机位 / 透视 / 景别

Agent C
人物姿态 / 重心 / 表情 / 指导

Agent D
光线 / 闪灯 / 曝光

Agent E
Cosplay / 武器 / 道具 / 服装空间

Agent F
现场执行 / 环境人像 / 漫展

Agent G
后期 / 色彩 / 筛片

Agent H
动态画面 / 运镜

Agent I
独立做 Coverage Audit，不参与最初建树

Agent J
独立做 Source Quality Audit

最后由主 Agent 合并。

主 Agent不得因为多个 Agent 都给出同一个结论，就把它视为多个独立来源。
必须回到真实外部资料。

━━━━━━━━━━━━━━━━━━
十二、非常重要
━━━━━━━━━━━━━━━━━━

宁可标：
“目前资料不足，待继续研究”

也不要凭模型记忆填满一棵看起来完整的树。

这套能力地图的价值就在于：

我未来几年都可以用它判断自己还缺什么。

所以：
“缺项”比“页面不好看”严重得多；
“假完整”比“暂时没完成”严重得多。
