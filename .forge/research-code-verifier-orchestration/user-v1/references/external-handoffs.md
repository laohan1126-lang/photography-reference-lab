# External handoffs

Use existing installed interfaces and provider routes. Probe their current `--help` before using flags. Locate the available executables or MCP capabilities; do not assume a filesystem path from another project. Do not read credentials into prompts/logs or switch authentication, models or provider merely to bypass a failure.

## Current project adapters

Read the current project instructions and applicable domain skill. If they supply a reviewed transport/runbook, use it within its exact context, source and writable-path boundaries. Match the handoff to the permitted transport: forbidding command execution while requiring a CLI makes the assignment impossible. A ROOT transport smoke is readiness evidence, not autonomous AGY research.

Missing domain transport or required access is a dependency to report and, when authorized, repair before substantive dispatch. Keep browser instances, source grants, profiles, policies, screenshots and other domain mechanics in that project; never copy another project's permission configuration into the user-level skill.

## AGY research

Provide a bounded goal and source-quality requirements, isolated cwd, exact evidence/material output paths and a finite timeout. Use installed print mode and structured output (`-p`, `--output-format stream-json`, `--print-timeout`) only after confirming current help. Select an available execution mode consistent with the required tools; plan mode may not produce material files. Retain existing permission controls and inspect each necessary denied action. Never use a skip-permissions switch to make headless research succeed.

Check the actual model response before debugging domain tools: API failure can occur before any tool. Do not repeat a non-retryable error without a relevant external-state change. For observation claims require actual source/browser/image-view events and traceable artifacts, not search metadata or agent prose. AGY supplies research materials and explicit limits; final copy remains a separate integration step.

## CC implementation

Provide the inspected baseline, frozen goal, exact owned paths, research input provenance and the existing architecture constraints. Use the current native print/structured-output interface after help inspection. Restrict tool access to what the task requires; preserve the tested Read/Edit/Write/Glob/Grep default without shell access. Scope Edit/Write to owned paths; exclude private credentials and independent Verifier files. A specific bounded shell command may be granted only when necessary and authorized.

Keep the configured provider route and project/user instructions/hooks unless an applicable authorized integration explicitly requires otherwise. Never assume flags or settings precedence are unchanged across CLI versions. Record any hook/configuration isolation and its effect; it is not proof of live hook compatibility. Require successful actual Read/Edit/Write events and an inspected diff. Codex/Verifier run relevant tests separately. A max-turn/timeout exit with partial edits remains incomplete until Codex explicitly integrates and validates those artifacts.

## Process capture and independent acceptance

Launch with argv arrays and an existing runtime, avoiding shell interpolation. Use UTF-8 evidence files in an ignored task-local directory. Write PID/start immediately; record end/exit/timeout in a finally path and retain partial output. On Windows background helpers are hidden. Stop only processes/sessions owned by the task, preserving shared services.

Treat output schemas as versioned. Inspect actual event fields and tool results rather than assuming AGY and CC use the same event shape. Store exact input/artifact hashes and record provider/transport context without secrets. Parallelize independent work only; share research with implementation after its evidence is available.

Verifier uses a fresh Codex context or independent subagent and separate repository worktree. Send only the goal/constraints before criteria freeze; later send the finished candidate paths and original evidence. Codex's final review checks that verdict, the actual work and user-goal coverage, then follows the current project's delivery rules.
