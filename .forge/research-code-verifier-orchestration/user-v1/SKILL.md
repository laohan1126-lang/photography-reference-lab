# Research Code Verifier Orchestration

## Decide and dispatch automatically

Given the user's goal, decide whether independent research, implementation or acceptance would improve the result. Codex chooses the necessary roles; the user need not name AGY or CC on every task. A complex implementation can use CC without research, and a research task need not create a coding assignment. Do not dispatch extra agents merely to consume quota.

Read the current project's instructions and inspect its real state. Honor current and standing authorization for the installed external agents; do not ask again for an already authorized in-scope action. This skill does not create authorization for another provider, paid API, new permissions or publication. If external-agent use is unauthorized, keep execution local and report the missing boundary.

This is the user-level v1 common workflow. A same-named project skill is not automatically merged with this package: inspect relevant project-scoped additions and preserve its constraints. Resolve domain methods and adapters from the current project and available domain skills. Never assume another project's browser, files, URLs, credentials or configuration are available.

## Roles and isolated ownership

| Role | Responsibility | Handoff |
| --- | --- | --- |
| Codex | Goal decomposition, acceptance design, scheduling, final review, integration and delivery | Requirements, dependency graph, exact writable paths |
| AGY | Information exploration, visual research, webpage/image/video understanding when a verified domain transport is available | Actual research evidence and source limits; not final course/product copy |
| CC | Code implementation, bounded refactoring and test repair | Real diff, evidence and unresolved issues |
| Verifier | Independent test design, red-team checks and failure reproduction | PASS / REVISE / BLOCKED with reproducible evidence |

For repository work create separate worktrees/branches from an inspected baseline. Give each execution and verification agent exact owned paths; never allow concurrent edits to a key file. Preserve unrelated dirty work. Do not initialize Git or create an agent platform merely to satisfy this procedure; report a required unavailable isolation boundary. ROOT alone integrates and publishes under the actual project's delivery authorization.

Start Verifier in a fresh context with only the goal, constraints and existing product interfaces. Do not send implementation conversations, agent prompts, self-assessments or suggested tests. Freeze observable criteria, hash and time before dispatching implementation. Reconcile the goal before freezing; never relax standards after observing results. Verifier later receives finished candidates and original evidence for inspection.

## Readiness and scheduling

1. Record intent, requirements, dependencies, ownership and any applicable delivery transaction before editing. Read [external handoffs](references/external-handoffs.md) before invoking installed agents.
2. Probe the current model entry point and a small representative operation through the task's actual transport. Record model, permissions, execution context, operation and returned artifact separately. An executable, logged-in UI or old successful run is insufficient.
3. Dispatch genuinely independent work in parallel. A generic compatible implementation may overlap research; content integration waits for research, and acceptance waits for the candidate. Respect dependencies rather than forcing all agents to run together.
4. Use real installed AGY/CC CLI or MCP interfaces. Never simulate an external agent with an internal Codex subagent. A necessary unavailable capability is BLOCKED; an authorized bounded setup repair is a separate dependency before resuming, not a silent provider substitution or permission bypass.
5. For each process record role, non-secret argv, cwd/branch/baseline, PID, UTC start/end, exit code, timeout/denied tools, owned paths and evidence locations. Preserve partial and failed attempts; resume from checkpoints instead of restarting successful work.
6. Inspect actual tool events, artifacts, diffs and tests. CLI SUCCESS/exit 0 proves only transport completion, not the task. Agent self-assessment is never acceptance. Keep missing evidence unknown.

## Independent acceptance and final Codex review

- **PASS:** every frozen criterion has actual complete evidence; distinguish engineering checks from human/domain acceptance.
- **REVISE:** give the failed criterion, reproduction, actual/expected behavior and responsible agent. Return source/evidence defects to AGY and implementation/compatibility/state defects to CC. Send the actionable failure rather than a new easier standard.
- **BLOCKED:** a necessary permission/input/capability is missing or two directed revision rounds have failed. Retain artifacts and report the precise blocker; resume after an actual resolving change.

Allow at most **two directed revision rounds per task** after the initial candidate. Review relevant prior failures/root cause before another fix. Rerun the failed check and affected regressions against unchanged frozen criteria; verify their hash before and after. Never delete failing tests, lower standards, edit Verifier to make a candidate pass or manufacture a failure to demonstrate revision.

After independent acceptance, Codex reviews the actual diff and evidence, confirms coverage against the user goal and checks unresolved findings and state/ownership protection. Codex integrates the accepted work and delivers the final result. Do not merely relay CC/AGY's final text or treat Verifier's verdict as permission to publish.

## Evidence, delivery and limits

Record selection, real dispatch, overlap when applicable, failures, directed revisions and final reruns. Distinguish VERIFIED, PARTIALLY VERIFIED, UNVERIFIED and BLOCKED. Follow only the current project's authorized Git/Notion or other delivery flow and report actual receipts separately. Publication does not prove product/domain acceptance. A claim of improvement over one agent needs a comparable baseline; otherwise report only the defects independently caught.

This skill does not solve browser permissions, perform video forensics, define photography research, choose human aesthetic judgments or design code architecture. Those belong to domain skills and user decisions. It installs no daemon, credentials or dependency, creates no automatic learning-state write and guarantees neither arbitrary website access nor unattended reliability.
